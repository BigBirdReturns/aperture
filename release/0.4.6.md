Aperture 0.4.6 separates return use of an exact managed GGUF from permission to contact the model host or transfer weight bytes.

Run the released package without Git:

```powershell
npx.cmd --yes --package=https://github.com/BigBirdReturns/aperture/releases/download/v0.4.6/bigbirdreturns-aperture-0.4.6.tgz aperture
```

On Linux or macOS, use `npx` instead of `npx.cmd`. Node.js 20.11 or newer is required. Distribution remains through GitHub rather than the npm registry namespace.

## What changed

A saved remote GGUF now checks its exact Aperture-managed acquisition entry before model-host metadata or weight-transfer approval. The cache identity binds the selected source, immutable revision, representation, component names, declared sizes, and expected hashes. Aperture admits only the matching regular files, then completely hashes every selected component and repeats native fit before loading.

An incomplete cache, missing component, symbolic entry, size drift, or identity drift remains a cache miss and follows the existing permissioned metadata, fit, and resumable-acquisition path. `--allow-download` authorizes downloading or resuming missing bytes; it is not required merely to reuse a complete matching managed artifact. Runtime installation and model execution keep their separate approvals. Safetensors remain on the existing verified acquisition path and do not receive this shortcut.

A separate Windows x64 host first populated Aperture's managed cache with Qwen2.5-0.5B-Instruct Q4_K_M at revision `9217f5db79a29953eb74d5343926648285ec7e67`. The selected artifact was 491,400,032 bytes with SHA-256 `74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db`; the request retained 2,048-token context and one sequence.

The executable candidate resumed the original saved remote selection without `--allow-network` or `--allow-download`. It reported no model-host request or weight transfer, repeated complete integrity and native-fit preparation, generated `FINAL CACHE PASS` on CUDA with 25 observed GPU layers, exited 0, released the selected GPU, and left no candidate-owned process. The attached path-free receipt excludes local paths, GPU UUIDs, and private run records.

## Retained capabilities

Release 0.4.6 retains the 0.4.5 reduced hardware support receipt and the 0.4.4 physical-capacity result. The latter ran a Qwen2.5-14B Q4_K_M checkpoint whose tensor payload exceeded the selected RTX 4060's reported physical memory through one qualified CPU/GPU split at 2,048-token context.

## Limits

This release establishes one exact managed-GGUF return-use path on one Windows x64 host. It does not authorize arbitrary cache imports, establish that checksum sidecars alone prove provenance, add a global cache search, add NPU numerical execution, qualify native Mac inference, implement distributed inference or pooled VRAM, broaden safetensors execution, prove model quality, or establish a general offline guarantee. Direct sources without publisher hashes retain their previously documented identity limitations.
