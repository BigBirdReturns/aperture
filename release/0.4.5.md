Aperture 0.4.5 adds a permissioned support-intake path so a hardware, fit, or backend failure can be reported without attaching the raw machine scan.

Run the released package without Git:

```powershell
npx.cmd --yes --package=https://github.com/BigBirdReturns/aperture/releases/download/v0.4.5/bigbirdreturns-aperture-0.4.5.tgz aperture
```

On Linux or macOS, use `npx` instead of `npx.cmd`. Node.js 20.11 or newer is required. Distribution remains through GitHub rather than the npm registry namespace.

## Reduced support receipt

Create a receipt with:

```sh
aperture support --allow-scan --out aperture-support.json
```

The command runs the same approved hardware inventory used by planning and writes a separate `aperture-support/1` JSON object. It retains CPU topology, RAM and allocation headroom, integrated and discrete graphics, NPU inventory, driver versions, storage classes and capacities, external-link observations, installed-runtime presence, provider status, and explicit unmeasured fields.

It excludes host and user names, local paths and mount labels, stable device and partition identifiers, GPU UUIDs, drive product names and serials, network adapter names and addresses, model locations, prompts, generated text, credentials, and environment variables. Dynamic provider errors are reduced to bounded classes. Labels shaped like PCI addresses, PnP identifiers, MAC addresses, or absolute paths are withheld.

The command accepts scan, destination, and output controls only. It does not inspect a model, contact a model host, acquire weights, install a runtime, execute inference, stress hardware, or upload the receipt. Existing output files are not overwritten.

## Privacy boundary

The receipt is reduced, not anonymous. Hardware model names, exact capacities, driver versions, current headroom, scan timing, and the receipt timestamp can still fingerprint a distinctive machine. Inspect the JSON before sharing it and remove any field that is unnecessary for the venue.

Raw scan, answer, and run records can contain paths, hardware identifiers, prompts, and generated output. The reduced receipt does not make those raw records safe to publish.

## Qualification

The package contains 162 source and control tests. The installed-package smoke path executes `aperture support` after a clean package installation on Node 22 and 24 across Windows, Ubuntu, and macOS. It parses the resulting JSON, verifies schema and version identity, rejects forbidden identifier fields, and rejects the runner's host name, home directory, and temporary path in all string values.

The package is built twice on the release branch and twice again immediately before publication. Publication proceeds only when the resulting byte count and SHA-256 match the reviewed manifest. The workflow refuses an existing tag or release, creates a versioned source archive and checksums, and dispatches post-publication documentation verification.

## Retained numerical evidence

Aperture 0.4.5 does not change the model-loading or inference path qualified in 0.4.4. The retained physical-capacity result used Qwen2.5-14B-Instruct Q4_K_M with 8,982,142,976 tensor bytes, exceeding the selected RTX 4060's 8,585,740,288 driver-reported physical bytes by 396,402,688 bytes. A qualified CPU/GPU split preserved 2,048-token context and one sequence, returned `42`, and exited successfully without selecting the separate RTX 3090 for model execution.

## Limits

This release does not establish anonymity, external native inference from a newly submitted receipt, arbitrary checkpoint compatibility, native Mac inference, NPU numerical execution, distributed inference, pooled GPU memory, optimal placement, task quality, or performance leadership. A support receipt is evidence about an observed machine state, not proof that a selected model will run.
