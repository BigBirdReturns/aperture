# Aperture public-interface binding

## Classification and provenance

This is a public tool site and operational documentation, bound to the AXM **dark ecosystem** family described in AXM House Style v1.2's two-family rule. It is not a Field Autopsy, cream editorial report, or the older `axm-aperture` project. The tool-console guidance in the later v1.3 binding also informs keyboard access, plain-language theme controls, mobile containment, and separation of states from their evidence.

The site retains the ecosystem's near-black field, teal signal, amber caution, thin rules, compact navigation, distinct display/body/evidence type roles, and an optional serif introductory role. It does not copy another product's metrics, operational claims, imagery, or control logic. The visual implementation is original; no third-party font files are redistributed.

## Tokens and interaction

`docs/assets/site.css` is the sole color/spacing/type-token authority for this site. Dark base is `#090a0b`, signal is `#1ab8a0`. The light variant adjusts foreground and signal colors for legibility instead of inverting images. The type stacks name Chakra Petch, Space Mono, and Source Serif 4 with system fallbacks; no external font request is necessary to use the site.

Auto, Light, and Dark describe actual behavior. There are no internal family names exposed as themes. A copy action copies a visible command and never executes it. The site does not claim to scan hardware. Illustrative workflow explanations are not presented as measured host output.

## Required review

Review desktop and narrow mobile widths in both color modes, keyboard focus, skip navigation, search, copy success and denied-clipboard behavior, no-JavaScript access, reduced motion, and print layout. There should be no horizontal page overflow or dependency on animation, color alone, or mouse hover for meaning.

A page has one title. Installation, capability, evidence, and recovery paths are discoverable from the navigation. Current limitations are close to the relevant decision without drowning the first useful action. Do not turn the release page into a collection of test-count trophies.

## Publication consistency

Documentation targets the explicit runtime release in `docs/site.json`. README commands, generated site commands, support statements, and actual public assets must agree. Pending pre-download native admission cannot be described as implemented until the executable changes and has its own evidence. The site and README do not imply automatic harness integration, NPU execution, physical-memory overrun qualification, or performance guarantees.
